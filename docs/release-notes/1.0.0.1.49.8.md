# Invio v1.0.0.1.49.8 — Sending Scheduler / Retry / Delay Controls

**Parent:** v1.0.0.1.49.7 @ `dd0cb058b2e85198e0e12f43680510ddfaee6f47`

## Implemented

- Task Network Timeout: 10–120 seconds, default 30.
- Maximum Automatic Attempts: 1–3, default 3.
- Additional Recipient Delay: 0–60 seconds, default 0; applied only between recipient executions.
- Provider rate override: provider default or a positive lower/equal per-account rate when a validated scheduling policy exists.
- Stripe ceiling: 20 req/s/account.
- Refrens ceiling: 1 req/s/account.
- Odoo: no declared numeric scheduling policy; custom rate remains unavailable rather than guessed.
- External runtime scheduling-policy validation hardened before policy values can become user-visible safety ceilings.
- New Tasks freeze sending controls into `TaskExecutionSnapshot`; Settings edits do not mutate existing Start/Resume/Retry behavior.
- SQLite schema v5→v6 adds only Task snapshot sending-control fields and preserves existing domain/P10 ledger data.

## Safety preserved

`Retry-After`, retryable status taxonomy, exponential backoff/jitter, account/provider cooldown, deterministic account binding/failover safety, ambiguous non-idempotent no-blind-replay behavior, Phase-1 Windows native TLS and Phase-2 provider fatal-limit circuit breaking remain authoritative. WorkerManager remains one QThread per active Task.

## Explicit non-goals

No Dynamic Tags, Odoo guessed RPS, provider payload redesign, OAuth/IVX change, new Task state, new page, parallel recipient executor, WorkerManager redesign or credential-storage change is included.
