# Invio v1.0.0.1.11

## P03 Verification & Correction

This release re-audits the shipped `v1.0.0.1.10` P03 implementation and corrects three P03 persistence-safety defects without adding P04 functionality.

### Corrected

- Migration backups now use SQLite live-backup semantics, so a version-1 database backup includes committed pages still present in WAL.
- Missing or unreadable protected credentials now durably downgrade the Account to `Not Verified` before startup completes. If the secret later becomes readable again, the Account remains non-executable until a real API Re-test succeeds.
- Account Edit now stages a durable `Not Verified` safety state before replacing protected credentials. A successful edit ends `Verified`; successful compensation restores the prior Account; failed compensation remains fail-closed rather than retaining a stale executable state.

### Regression coverage

The storage/account suite now includes committed-WAL migration-backup fidelity, durable credential-loss downgrade, final Account Edit database rollback, and rollback-compensation failure contracts.

### Scope preserved

P03 remains 3/14 production phases complete. No new page, dependency, provider manifest, Customer/Invoice/Task model, WorkerManager/ProviderManager architecture, provider send behavior, credential-storage technology, or schema version is introduced. P04 remains pending owner approval.

Native PySide6 rendering, native OS keyring integration, and live Stripe/Refrens certification are not claimed by this local audit environment and remain within the later certification boundary.
