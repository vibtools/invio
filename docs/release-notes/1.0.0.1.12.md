# Invio v1.0.0.1.12

## P04 - Customer Data Contract and Import Upgrade

This release completes the approved P04 phase on top of the verified `v1.0.0.1.11` baseline.

### Added

- Provider-neutral `CustomerRecord` with mandatory normalized email and optional explicit name/country.
- Structured CSV/TSV/XLSX/XLSM customer import using `email`, `name`, `country` headers.
- Legacy email-only compatibility for TXT and files without a structured `email` header.
- Row-numbered validation for missing/invalid email, invalid country and conflicting duplicate rows.
- Deterministic duplicate handling and explicit enrichment of previously blank customer metadata.
- SQLite schema v3 customer metadata persistence with WAL-aware migration backup.
- Customer-aware Task runtime snapshots with a backward-compatible email view.
- Customer Lists UI columns for Email, Name and Country plus bounded import-result summaries.

### Preserved

- `CustomerList.emails`, `AppState.add_emails()` and `import_emails()` remain compatible.
- Stripe customer lookup/create and invoice sending continue to use email exactly as before.
- Customer/billing/shipping/payment data remains outside Invoice Templates.
- ProviderManager, WorkerManager, Account/Invoice/Task models, provider manifests and dependencies are unchanged.
- Refrens production Task execution remains disabled until P11.

### Migration

Schema v2 databases migrate transactionally to v3. Existing ordered email rows receive blank `name` and `country`; no value is guessed. A pre-migration SQLite backup is created before the upgrade.

### Remaining production boundary

P05 will define immutable Task-creation execution snapshots so later Customer List/template edits cannot change an existing run. Refrens end-to-end sending remains P11. Live/native certification remains P14.
