# Invio v1.0.0.1.24

## P08 forensic verification correction

Parent baseline: `v1.0.0.1.23`.

This release corrects only defects found while re-auditing the shipped P08 Worker and Network Reliability implementation.

### Corrected

- `http.client.IncompleteRead` during a successful-status response body is classified as a retryable transient network disconnect instead of escaping as an unexpected recipient exception.
- TLS EOF/clean-close interruptions are retryable transient disconnects; certificate verification and non-transient TLS errors remain permanent.
- An HTTP error whose body is truncated still preserves its known HTTP status and `Retry-After` header for the existing P08 retry decision.
- Private P08 completion/error-handling records are synchronized to 8/14 complete, 6/14 remaining, P09 next.

### Preserved

- maximum three total recipient attempts;
- 0.5s/1.0s exponential backoff before jitter and the existing jitter/cap policy;
- same recipient, same account and same Stripe idempotency keys during retry;
- 30-second shared urllib timeout policy;
- cooperative Pause/Stop and asynchronous safe shutdown;
- one Task = one QThread;
- P05/P06/P07 behavior;
- Stripe/Refrens/Agiled provider behavior outside this classification correction;
- SQLite schema v4 and dependencies;
- no P09+ implementation.

Native Qt/keyring and live-provider certification remain P14 scope.
