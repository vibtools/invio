## Audited GitHub failure

GitHub Actions run `31374749523`, Windows job `93411358955`, checked out commit `3fb7017bb56c7f65328c58e1195df8927944bda5`.

The Windows job passed the full `381/381` regression audit, workflow version mapping, wheel build/install, native PySide6/keyring/resource smoke, Nuitka OneDir build, portable preparation and compiled OneDir startup smoke before reaching **Install WiX Toolset**.

The command:

```powershell
dotnet tool install --global wix --version $env:WIX_VERSION
```

successfully installed WiX Toolset `6.0.2`. The subsequent CLI query returned:

```text
6.0.2+b3f3403
```

The v1.36 workflow then compared that full informational string directly with `WIX_VERSION=6.0.2`, incorrectly raising `Installed WiX version is stale`.

## v1.37 correction

The package pin remains exactly `6.0.2`. The workflow now:

1. trims `wix --version`;
2. derives the canonical core version by removing only an optional `+build-metadata` suffix;
3. compares that canonical value with the pinned `WIX_VERSION`;
4. still fails closed when the core version differs.

No WiX package upgrade/downgrade, installer redesign, dependency change, provider change, schema change, Task/WorkerManager change or UI/UX change is included.
