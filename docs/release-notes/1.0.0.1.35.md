`v1.0.0.1.35` is a scope-locked P14 verification/distribution correction built from the owner-frozen `v1.0.0.1.34` certification candidate. It adds the explicitly approved Windows end-user distribution pipeline without changing provider business logic, Task/WorkerManager behavior, SQLite schema v5, the P13 external-adapter interface, customer/template models, Settings, Reports/Logs, or the frozen page inventory.

## Windows distribution pipeline

GitHub Actions now keeps the existing Ubuntu and native-Windows regression/wheel gates and additionally builds:

- a **Nuitka 4.1.3 OneDir** Windows x64 application using the PySide6 plugin;
- a versioned **portable ZIP** containing the complete OneDir application;
- a **WiX Toolset 6.0.2 MSI** installer generated from the exact OneDir file inventory;
- the existing setuptools **wheel**, retained as a Python packaging/certification artifact;
- `SHA256SUMS.txt` covering the portable ZIP, MSI, and wheel.

The build-only Nuitka and WiX tools are pinned in GitHub Actions and are not added to Invio runtime dependencies.

## Installer behavior

The MSI installs per-user under `%LOCALAPPDATA%\\Vib Tools\\Invio`. This is deliberate: the frozen P13 provider registry is writable runtime state under the application root, so a per-user writable installation preserves the existing Load/Install/Uninstall Provider workflow without UAC or a provider-storage architecture change.

The pipeline performs a silent MSI install, launches the installed executable in an offscreen smoke environment, verifies startup reaches durable storage creation, and then silently uninstalls the MSI.

## GitHub push and release behavior

Every normal push and pull request executes regression plus Windows distribution build/artifact upload. The workflow grants only `contents: read` to normal build jobs.

For an exact release tag such as `v1.0.0.1.35`, the tag is validated against `pyproject.toml`. After the test and Windows-build jobs succeed, the tag-gated release job receives `contents: write` and publishes the versioned portable ZIP, MSI, wheel and checksum file to the GitHub Release. A stale/mismatched tag fails before publishing.

## Local verification boundary

The source/build pipeline, mapping helpers, deterministic WiX generation, portable assembly and repository regressions are locally testable. The actual Nuitka compilation, WiX MSI build/install and Windows native runtime smoke require the GitHub `windows-latest` runner and therefore are **NOT EXECUTED** until this exact candidate is pushed.

Owner-controlled live Stripe Test/Live credentials and Refrens live API/invoice/mailbox evidence were also not supplied in this implementation workspace. Therefore **P11 and P14 are not marked COMPLETE and Invio is not described as production-ready**.
