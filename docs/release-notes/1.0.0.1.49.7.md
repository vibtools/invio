# Invio v1.0.0.1.49.7 — CI Release-Audit Correction

## Parent baseline

- Invio v1.0.0.1.49.6
- Git commit `7ec5ea38c620af26430d862aba5373a903b95bff`

## Verified failure

GitHub Actions run `32084087751`, Windows job `95552861559`, passed the full 545-test regression suite, wheel build/audit, clean wheel install, native PySide6/keyring/resource smoke, Nuitka OneDir build/startup, compiled credential smoke, compiled Windows native TLS smoke, WiX MSI build, and MSI install/run/uninstall smoke. The job failed only in `Assemble release payloads and checksums` because `p14_distribution_audit.py` required `Invio/truststore/__init__.py` inside the portable ZIP.

## Root cause

The v1.49.6 distribution audit confused a Python source-package layout with a compiled Nuitka runtime contract. Nuitka compiled the included `truststore` dependency successfully, as proven by the earlier executable TLS smoke gates, but did not retain the original `truststore/__init__.py` source path in the standalone directory. The synthetic unit fixture created that source file, so the false assumption was not exposed before the real Windows build.

## Correction

- Remove `Invio/truststore/__init__.py` from the static portable file inventory.
- Remove the synthetic `truststore/__init__.py` fixture from P14 distribution tests.
- Add a regression assertion that the portable audit does not depend on compiled Python source layout.
- Keep the compiled OneDir and MSI-installed `INVIO_P14_COMPILED_TLS_SMOKE` gates as the authoritative runtime proof.
- Advance application identity to v1.0.0.1.49.7.

## Frozen behavior

Phase-1 native Windows TLS verification, Phase-2 external-provider fatal-batch circuit breaker, Odoo provider v1.0.1, WorkerManager/QThread, Task state machine, delivery ledger, SQLite/storage/CredentialStore, OAuth/Easy Onboarding, IVX/provider loading, Settings, retry/rate/delay behavior, Dynamic Tags, and MSI/WiX architecture are unchanged.
