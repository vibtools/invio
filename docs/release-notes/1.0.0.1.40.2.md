## Scope

This correction is limited to the owner-supplied current Agiled OpenAPI evidence and the owner-observed Refrens API mail rejection.

### Agiled

The supplied `openapi.yaml` identifies `Agiled Public API` version `1.0.0` / OpenAPI `3.1.0`, HTTP Bearer authentication, `GET /public/v1/me`, invoice CRUD under `/public/v1/invoices`, and Idempotency-Key guidance for create operations.

Invio now enables only the part of that contract that is fully specified and safe: **Agiled API Test**. The built-in API Test performs exactly one side-effect-free request:

`GET https://api.agiled.ai/public/v1/me`

with the protected API key in `Authorization: Bearer <key>`.

Agiled Task sending remains fail-closed. The supplied OpenAPI contains no invoice email/send operation, and its generic `MutationRequest` does not publish a field-level invoice request contract. The unrelated `/public/v1/documents/{documentId}/send` operation is not treated as an invoice-send endpoint. Invio therefore does not invent invoice fields or an email endpoint.

### Refrens

The live v1.40.1 run proves that Refrens authentication and invoice creation succeed, then the documented explicit invoice email endpoint returns deterministic `HTTP 400` with provider message `Not allowed to send mail`.

The current runtime path and payload already match the documented Refrens post-create email operation. This is therefore a **provider-side API mail permission/capability rejection**, not a URL, JSON-shape, authentication, retry, invoice-create, Task-state, WorkerManager or SQLite defect. Invio cannot safely bypass that provider restriction.

v1.40.2 preserves the explicit send operation and duplicate-invoice-safe retry behavior, but now emits the HTTP status as a separate provider log entry, for example:

`CODE 400`

The existing durable ledger continues to record the machine-readable `HTTP_400` error code.

## Unchanged

- SQLite schema remains v5.
- WorkerManager and one-QThread-per-active-Task architecture are unchanged.
- Refrens authentication, trusted host, invoice-create payload, invoice-ID reuse and explicit email endpoint/payload are unchanged.
- Stripe behavior is unchanged.
- Agiled has no Task runner and makes no invoice mutation.
- Provider credential field shapes and runtime dependencies are unchanged.
- No page, workflow, database schema or UI architecture is added or redesigned.
