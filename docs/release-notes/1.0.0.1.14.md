# Invio v1.0.0.1.14

## Windows Operational Storage Runtime Hotfix

This release is a scoped correction on the verified `v1.0.0.1.13` P04 baseline. It does not begin P05 and does not change application features, UI/UX, provider behavior, WorkerManager architecture, protected credential storage, or SQLite schema version.

### Fixed

On Windows, startup migration could fail with an error similar to:

```text
Could not create the pre-migration backup: [WinError 32]
The process cannot access the file because it is being used by another process:
domain.sqlite3.pre_migration_v1.bak.tmp -> domain.sqlite3.pre_migration_v1.bak
```

The migration backup was created with SQLite's live backup API, but the destination connection was opened with `with sqlite3.connect(...)`. Python's SQLite connection context manager commits/rolls back on exit but does not close the connection. Windows therefore still held the temporary backup file open when `Path.replace()` attempted the atomic rename.

`DomainStore._create_migration_backup()` now explicitly closes the destination SQLite connection before the temporary file is replaced.

### Preserved

- SQLite schema remains **v3**.
- WAL-aware live backup semantics remain unchanged.
- Existing v0/v1/v2-to-v3 migration order remains unchanged.
- Corrupt/newer/unrecognized databases remain fail-closed and are not silently overwritten.
- Provider credentials remain in approved OS-protected keyring storage with no plaintext fallback.
- ProviderManager, WorkerManager, Stripe/Refrens execution contracts, Customer Lists, Invoice Templates, Tasks, Accounts and current UI remain unchanged except release-version metadata.
- Production progress remains **4/14 phases complete**. P05 remains the next separately approved phase.

### Verification

A platform-neutral regression test asserts that the migration backup destination is explicitly closed before the atomic replacement. The full repository test/audit suite is required to pass before this release becomes the next baseline.
