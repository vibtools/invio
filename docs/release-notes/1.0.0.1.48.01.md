# Invio v1.0.0.1.48.01

Parent Official Baseline: `v1.0.0.1.48.0`.

This scope-locked hotfix fixes only the **Task Close confirmation** path. The Tasks page button wiring, central `TaskAction.CLOSE` policy, active-worker guard, `AppState.close_task()`, durable `DomainStore.delete_task_and_release()`, account-reservation release, historical delivery-ledger retention and post-close UI refresh were forensically verified as intact.

The regression boundary is the Windows confirmation surface introduced by custom-chromed `QMessageBox`: the Close Task confirmation did not explicitly force Qt's widget dialog path before custom properties/chrome were applied. `v1.0.0.1.48.01` opts only the Close Task confirmation into `QMessageBox.Option.DontUseNativeDialog` before title/text/buttons and custom chrome are configured. Other confirmation workflows are unchanged.

Version mapping: application `1.0.0.1.48.01`, PE `1.0.1.4801`, MSI `1.1.4801`.
