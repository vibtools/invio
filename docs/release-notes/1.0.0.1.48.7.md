# Invio v1.0.0.1.48.7 — Global Status Badge Rendering & Table Cell Alignment Fix

**Parent Official Baseline:** `Invio v1.0.0.1.48.6`

## Scope

This release changes only global UI status rendering and directly required verification/release records. It does not change backend/provider/business/storage/API behavior.

## Root correction

The duplicated status symptom came from table consumers doing both operations on the same cell:

1. inserting a visible `QTableWidgetItem` containing the raw status; and
2. overlaying a transparent badge widget with the same status.

The existing shared UI layer now owns the canonical path. `set_data_status_cell()` stores the raw status only in `Qt.UserRole` and tooltip metadata, inserts no visible raw status text, and installs one centered semantic badge.

A Windows verification correction also fixes the sizing contract: the visible badge size, not the host widget's aggregate size hint with centering stretches, now drives the table-item size hint. This keeps compact fixed Status columns valid and prevents ResizeToContents consumers from expanding unnecessarily.

## Global consumers audited

- Accounts flat table: shared canonical status cell.
- New Task account table: shared canonical status cell.
- Reports task and delivery tables: shared canonical status cells.
- Tasks: canonical shared status badge; redundant raw Status metric removed.
- Providers: canonical shared status mapping for Verified/Available.
- Customer Lists, Live Logs and Settings: no duplicate status-badge table consumer exists; no layout/behavior change was made.
- Dialog inline API-test messages remain the existing inline feedback component because they are full feedback messages rather than duplicated status-value cells.

## Semantic UI
