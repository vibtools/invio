# Invio v1.0.0.1.48.02

## Scope
Global QMessageBox / Popup Lifecycle Functional Regression Fix over the owner-frozen `v1.0.0.1.48.01` baseline.

## Root cause and correction
The custom-chrome path passed a caller-captured Qt-owned `QMessageBox.layout()` into `install_dialog_chrome()`. Applying frameless/translucent window mutations could cause Qt to rebuild that internal layout, leaving the earlier Shiboken `QGridLayout` wrapper stale. Accessing its margins then raised `libshiboken: Internal C++ object ... already deleted` and aborted the calling UI slot.

`v1.0.0.1.48.02` forces every Invio-owned compact message box onto `QMessageBox.Option.DontUseNativeDialog` before message configuration and custom chrome. `install_dialog_chrome()` now performs the window mutation first and then reacquires the live `dialog.layout()` before reading or changing margins. The historical Close Task opt-in argument is retained for internal source compatibility, but widget-backed behavior is now global for all existing warning/error/info/confirmation flows.

Real PySide6 modal interaction tests cover information, warning, critical and question boxes, parented dialog use, button return values and reopening. No business logic, state-machine, WorkerManager, provider, storage, customer/invoice, settings or unrelated visual behavior is changed.

Version mapping: application `1.0.0.1.48.02`, PE `1.0.1.4802`, MSI `1.1.4802`.

## Python wheel packaging compatibility
The public Invio application and tag identity remains exactly `1.0.0.1.48.02` / `v1.0.0.1.48.02`, and Windows portable/MSI filenames continue to use that public identity. Python packaging canonically normalizes the final numeric segment `02` to `2`, so the wheel metadata and wheel release filename are expected as `1.0.0.1.48.2` and `invio-1.0.0.1.48.2-py3-none-any.whl`. P14 now validates that mandatory canonical wheel identity without changing runtime, UI, business logic, PE/MSI versions or release-tag identity.
