# Invio v1.0.0.1.29 - P11 Refrens End-to-End Task Implementation Candidate

## Status

**P11 IMPLEMENTED / LIVE ACCEPTANCE PENDING.** Production progress remains **10/14**. `v1.0.0.1.28` remains the latest completed-phase Official Baseline until the owner-supplied live Refrens acceptance gate passes.

## Implemented

- Built-in Refrens Task runner using immutable explicit customer Email, Name and Country.
- Exact canonical Refrens API-host validation before App ID/App Secret construction/transmission.
- Preflight block for missing required customer data and for Indian recipients because the approved Invio customer model has no GST State field.
- Deterministic frozen account assignment, 1 request/second/account Invio safety pacing, provider-wide health handling and exact attempted-account binding.
- Maximum-three-attempt P08 retry for authentication only.
- Single-shot invoice-create/email mutation; ambiguous network/408/5xx outcomes become durable P10 `Uncertain` evidence and are not blindly replayed.
- Write-ahead `refrens_authentication` and `refrens_invoice_create_email` P10 operation evidence; returned invoice `_id` is persisted as provider invoice/reference evidence.
- Refrens uncertain-only continuation is disabled in the existing Tasks action UI; no new page is added.

## Preserved

- SQLite schema v5 and exactly three P10 delivery-ledger tables.
- One Task = one QThread; no concurrency redesign.
- P05-P10 behavior, Stripe flow, Agiled fail-close, packaged provider manifests, dependencies and customer model.
- No JWT, App Secret or guessed provider idempotency data is persisted.

## Live acceptance required

P11 must not be marked COMPLETE until an owner-supplied Refrens environment verifies all three: successful live API Test, real invoice creation, and actual recipient email delivery. Those live checks were not available for this candidate build.
