# Invio v1.0.0.1.48.5

## Scope

**Accounts Page — Compact Flat Account Table & Semantic Status UI** over the frozen `Invio v1.0.0.1.48.4` baseline. Only Accounts-page presentation and directly required verification/release records change.

## Root cause

The baseline Accounts page renders provider parent rows with expandable account children and keeps Edit / Re-test / Delete as page-header actions driven by tree selection. This duplicates provider-level presentation, consumes scanning space with Mode / Last API Test / Assigned Task / Credentials columns, and makes large provider account sets dependent on expansion rather than a direct account list. The underlying account callbacks, verification, persistence, provider relationship and task-assignment behavior were already functional.

## Update

- Page header keeps only **Add Account**.
- Replaces the provider/account `QTreeWidget` hierarchy with one flat `QTableWidget`.
- Final columns are `ACCOUNT`, `PROVIDER`, `STATUS`, `ACTION`.
- `Added Accounts List`, Search, Provider filter and Status filter share one compact toolbar row.
- Existing pagination and rows-per-page controls are preserved for large account sets.
- Each account row exposes the existing `Edit`, `Re-test` and `Delete` actions through a compact `⋯` menu.
- Existing status colors are applied semantically: success/ready green, verification attention amber, not-installed/error red, unavailable/disabled neutral gray; blue remains the existing primary/selection color.
- Search continues to include existing account/provider/status/mode/verification/task/credential metadata even when redundant scan-only columns are no longer displayed.

## Functional preservation

No AppState model, provider relationship, API-test/re-test behavior, protected credential flow, task reservation rule, callback, persistence contract, provider runtime, WorkerManager or non-Accounts page behavior changes.
