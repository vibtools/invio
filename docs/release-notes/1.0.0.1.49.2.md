# Invio v1.0.0.1.49.2 — Provider Easy Onboarding Compatibility Correction

**Official Parent Baseline:** `Invio v1.0.0.1.49.1 Provider Easy Onboarding V1` replace-ready delta state.

## Verified root cause

The owner-supplied native Windows audit executed 504 tests and exposed one real runtime compatibility regression in `AddAccountDialog`. Provider Easy Onboarding V1 is an optional additive capability, but the dialog called `provider_runtime.supports_onboarding(...)` directly while constructing its provider controls. Existing Browser-OAuth-only runtime collaborators that correctly predate the onboarding capability therefore raised `AttributeError` before the dialog could render.

The failure was not a provider-send error, OAuth protocol error, WorkerManager error, storage error, or MSI failure. It was a capability-detection compatibility defect at the Add Account UI/runtime collaboration boundary. Forensic continuation of the unchanged native regression test also exposed the next legacy assertion that would have failed after the exception was removed: Browser-OAuth-only runtimes must retain the established `Connect once in your browser...` status copy rather than inheriting Quick Connect messaging. Both defects share the same root cause: Easy Onboarding behavior leaked into the legacy Browser OAuth-only path.

## Exact correction

- `AddAccountDialog` now detects `supports_onboarding` with an optional callable lookup.
- Missing `supports_onboarding` means Easy Onboarding is unsupported for that runtime collaborator; it does not make Add Account fail.
- `onboarding_profile` is likewise queried through an optional callable lookup.
- Real `ProviderRuntime` Quick Connect behavior remains unchanged when the onboarding interface is present.
- Browser OAuth remains available to Browser-OAuth-only runtimes without requiring the newer onboarding methods.
- Browser-OAuth-only status copy remains exactly on the established legacy path; Quick Connect status copy is selected only when onboarding is actually supported.
- Existing Advanced / Manual Setup and existing-account compatibility remain unchanged.

## Frozen boundaries

No provider Task/send semantics, External Provider Adapter v1 execution behavior, Browser OAuth v1 protocol behavior, provider bundle send implementation, WorkerManager/QThread architecture, Task state machine, retry/resume/delivery-ledger semantics, SQLite schema, protected credential storage, customer/template/report business logic, provider install/uninstall architecture, MSI/WiX behavior, dependency stack, or unrelated UI/UX is changed.

The five Easy Onboarding companion provider bundles remain at **v1.2.0** because forensic comparison and their deterministic provider suites found no provider-bundle defect requiring a new plugin version.
