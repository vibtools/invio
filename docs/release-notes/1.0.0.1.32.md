# Invio v1.0.0.1.32 — P13 Executable External Provider Adapter Contract

P13 completes the executable external-provider adapter contract. External providers may remain manifest-only or may supply a fixed sibling `adapter.py` with a versioned `runtime_adapter` declaration. Executable code requires explicit trusted-code confirmation and runs as trusted in-process Python, not as sandboxed code.

The provider bundle is staged before registry replacement. Invio validates the staged bytes, rejects validation-time mutation, checks provider/interface/adapter/profile/capability identity, contains module/entrypoint `BaseException` failures, rejects/restores persistent `sys.path` mutation, and fails closed on missing or incompatible adapters. No remote code download, dependency auto-installation or framework replacement is introduced.

External API Test and Tasks reuse the existing P01/P05/P06/P08/P10/WorkerManager boundaries. API Test requires at least one successful host-managed `SAFE_READ`. Task validation/execution receives isolated template data, and recipient success requires host-managed mutation evidence with an exact final-stage match. Host operations distinguish `SAFE_READ`, `IDEMPOTENT_MUTATION`, and `NON_IDEMPOTENT_MUTATION`; ambiguous non-idempotent outcomes, post-success adapter failures, and interrupted recipient finalization after non-idempotent mutation remain `Uncertain` rather than being blindly replayed. Optional P09 scheduling applies only when an adapter explicitly supplies it.

P10 restart interpretation recognizes successful external non-idempotent mutation without provider idempotency evidence as unresolved when recipient finalization was interrupted. SQLite remains schema v5 with exactly the existing three delivery-ledger tables; built-in Stripe/Refrens business behavior and existing P10 semantics remain unchanged, and Agiled remains fail-closed. Executable external replacement/uninstall is blocked while a current Task references the provider because Task snapshots do not persist external adapter versions.

P13 is COMPLETE by automated architecture/contract acceptance. P11 remains **IMPLEMENTED / LIVE ACCEPTANCE PENDING** because owner live Refrens API/invoice/email acceptance has not been supplied. P14 final native/live/packaging production certification remains pending.
