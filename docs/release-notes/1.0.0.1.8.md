# Invio v1.0.0.1.8

**Release date:** 2026-08-08  
**Production phase:** P02 - Durable Domain Storage and Protected Credentials

## Added

- SQLite schema-v1 persistence for approved non-sensitive Accounts metadata, Customer Lists/emails, Invoice Templates/items/terms, Tasks/task accounts/counters/messages, and account reservations.
- Owner-approved protected provider credential storage through `keyring`, with no plaintext fallback.
- Startup state reconstruction, missing-secret fail-closed recovery, and active-Task recovery to existing `Stopped`.
- Transactional state writes, migration backup/version rules, corruption/future-schema rejection and persistence-failure handling.

## Unchanged

- P01 API verification behavior and verified-account gates.
- Provider manifests/IDs/credential fields.
- Stripe/Refrens invoice runtime behavior.
- Existing WorkerManager one-QThread-per-active-Task architecture.
- Existing application pages/UI workflows.

## Deliberate boundary

P02 does not implement persistent per-recipient delivery attempts, provider customer/invoice IDs, restart-safe Retry Failed state, or remote-provider crash reconciliation. Those remain P10. Native Qt/OS-keyring/live-provider certification remains P14.

## Post-release verification note

A later forensic re-audit of the exact v1.0.0.1.8 artifact found two P02 defects in a failure/recovery boundary that the original tests did not cover. They are corrected and regression-tested in v1.0.0.1.9. P02 architecture and approved technology remain unchanged.
