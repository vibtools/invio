# Invio 1.0.0.1.2

**Release date:** 2026-08-07  
**Baseline:** `v1.0.0.1.1`  
**Scope:** provider uninstall and compact modal UI only, plus directly required backend wiring, tests, version metadata, forensic verification, and synchronized documentation.

## Provider uninstall

Installed provider cards now expose **Uninstall**. The action is routed through the existing Providers page callback boundary to `MainWindow`, then to `ProviderManager.uninstall()`.

Uninstall behavior is intentionally narrow:

- validates that the provider is currently installed;
- removes only `providers/registry/<provider-id>.json`;
- does not delete bundled provider packages;
- does not delete current in-memory accounts or tasks;
- bundled providers return to the **Available** state and can be installed again;
- provider manifests remain non-executable metadata.

## Compact modal update

Application-owned dialogs now use a shared parent-relative compact geometry helper.

- **Add Account:** wider and shorter; Provider/Mode use two columns, Account name spans the form width, and provider credentials use two columns only when more than two fields are declared.
- **Invoice Template:** existing Template Settings and Invoice Content are placed side by side to reduce vertical height; no template field or behavior changed.
- **New Task:** uses the shared compact geometry and a shorter account-list minimum height; selection/reservation rules are unchanged.
- **New Customer List:** uses the shared compact geometry.
- **Message/confirmation boxes:** routed through one compact application-owned message-box path.
- Native operating-system file/folder picker dialogs are unchanged.

## Regression protection

No page, provider ID, provider credential schema, capability, account mode, account/task/customer/template model, Settings behavior, worker-thread contract, dependency, or provider runner contract was removed, renamed, or replaced.
