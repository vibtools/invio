# Invio v1.0.0.1.23

## P08 - Worker and Network Reliability

This release completes P08 on the `v1.0.0.1.22` Official Baseline. It keeps one task-owned QThread per active Task and does not change provider invoice business logic, account assignment, database schema, dependencies or UI page inventory.

### Reliability changes

- structured retryable/permanent provider-network failure metadata;
- maximum three total attempts per recipient;
- exponential retry delay of 0.5s then 1.0s before 0-25% jitter, with 8s exponential cap;
- `Retry-After` numeric/HTTP-date parsing for retryable responses;
- timeout/disconnect/408/429/500/502/503/504 transient classification;
- deterministic 4xx, invalid response and TLS certificate verification failures remain permanent;
- explicit 30-second shared urllib socket timeout policy;
- Pause/Stop-aware retry waiting;
- retry uses the same account and existing Task.id-derived Stripe idempotency keys;
- unexpected recipient exceptions are isolated and counted once;
- application shutdown waits asynchronously for every active task QThread to finish and never force-terminates a worker.

### Preserved boundaries

P09 account failover/rate scheduling, P10 delivery ledger, Refrens P11 Task sending, Agiled execution and P13 external executable plugin loading remain unimplemented. SQLite stays schema v4. No dependency or UI-page change is included.
