# Invio v1.0.0.1.49.9 — Windows Phase-3 CI Correction

Parent: Invio v1.0.0.1.49.8 / Git commit `c9712add5ac6b4b41b3c1bc999a21e1767bc3822`.

## Confirmed failure

GitHub Actions run `32097949119`, Windows job `95592816900`, reached the full 629-test regression suite. All Phase-3 sending-control, scheduling, provider, TLS and PySide6 UI interaction tests passed. The only clean-checkout failure was:

`Phase3SendingControlStorageTests.test_schema_v5_migrates_to_v6_with_baseline_safe_defaults`

Windows cleanup raised `PermissionError: [WinError 32]` for the temporary `domain.sqlite3`.

## Root cause

The test used `with sqlite3.connect(db_path) as connection:` twice. SQLite's connection context manager controls the transaction but does not close the connection object. Windows therefore still had the test fixture's database file open when `TemporaryDirectory` attempted deletion. Production `DomainStore` already closes every `_connection()` in a `finally` block and was not the source of this failure.

## Correction

Both migration-fixture connections now use `closing(sqlite3.connect(db_path))`. No production storage implementation, migration SQL, schema, provider behavior, Settings semantics or UI workflow is changed.

Version mapping: application `1.0.0.1.49.9`, PE `1.0.1.4909`, MSI `1.1.4909`, wheel `1.0.0.1.49.9`.

No tag/release should be created until the new non-tag GitHub CI is green.
