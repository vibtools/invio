# Invio v1.0.0.1.6

## Scope

Production hardening phase **P01 - Real Account API Verification** only. Baseline: `v1.0.0.1.5`.

## Added / Changed

- Add Account API Test now executes the existing Stripe/Refrens provider verification adapter instead of reporting required-field validation as an API test.
- Provider network verification runs on a dedicated dialog-owned `QThread`, keeping the GUI thread responsive.
- Stripe API Test enforces selected Test/Live mode before checking customers and invoices access.
- Refrens API Test authenticates with app-secret credentials and checks invoice-list access.
- Successful verification creates the account with current-session status `Verified`. Provider/mode/credential changes invalidate the prior result.
- Providers without an executable built-in API-test adapter show API Test as unavailable.
- New Task selection, backend Task creation, Start, and Retry reject accounts that are not `Verified`.
- API-test failure messages/logs are scrubbed against submitted credential values before display/logging.

## Unchanged

Provider manifests and credential fields/modes/IDs, invoice templates, customer lists, provider send workflows, task WorkerManager architecture, settings, reports/logs UI, dependencies, and persistence behavior remain unchanged.

## Remaining production work

P02 is next: durable domain storage and an owner-approved protected credential mechanism. Account verification remains current-session state until that phase. Live provider-environment certification remains P14.
