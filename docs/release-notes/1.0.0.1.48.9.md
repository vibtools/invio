# Invio v1.0.0.1.48.9 — Customer Lists Compact UI + Global Header Standardization

**Official Parent Baseline:** Invio v1.0.0.1.48.8.

This release is UI-only. It finalizes the Customer Lists page as a compact two-panel workspace and applies the already-established compact page/section toolbar hierarchy to the remaining applicable pages without changing backend, provider, storage, task, API, validation, navigation, popup or business behavior.

## Customer Lists

- Page header remains `Customer Lists` with the existing `New List` action.
- The left side is now a compact scrollable Customer List navigation panel rather than a two-column data table.
- Each list row shows the list name, a small muted customer-count badge and a row-scoped `⋯` menu. The existing delete callback remains the list action.
- Existing list search and record-state filtering remain available in the same compact Lists section toolbar; the `＋` control calls the existing New List callback.
- The Customers section now places title, search, Country filter and `Upload` on one row.
- Customer rows remain data-only with `# / EMAIL / NAME / COUNTRY`; no customer Action column is added.
- Existing customer search, country filtering, upload callback, pagination and rows-per-page behavior remain unchanged.
- List-row menus use the shared window/screen-bounded popup geometry helper so they stay inside the Invio application boundary.

## Global compact header rollout

- Shared `page_header()` remains the canonical page-header path.
- `DataGridToolbar` now supports an optional section title and section actions on the same compact row while preserving the existing search/filter API.
- A shared `section_toolbar()` is used for non-table section controls.
- Invoice Templates and both Reports grids now place their section titles on the same row as search/filters.
- Providers uses `Provider Catalog + Search` on one compact section row.
- Settings separates page-level Reset/Save actions from the `Preferences + Search` section row.
- Accounts, Dashboard, Tasks and Live Logs already matched the frozen compact hierarchy and retain their established behavior/layout contracts.

## Frozen boundaries

No provider/runtime logic, WorkerManager architecture, task state machine, SQLite schema/storage, account/customer/invoice data model, authentication, API behavior, import parsing, validation or dependency changes are included.

Version mapping: application/tag `1.0.0.1.48.9` / `v1.0.0.1.48.9`, PE `1.0.1.4809`, MSI `1.1.4809`, Python package/wheel `1.0.0.1.48.9`.
