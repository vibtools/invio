## Owner-observed live failure

The released `v1.0.0.1.38` application successfully completed a real Refrens **API Test** and displayed `Refrens API connection verified.`. The immediately following **Add Account** action then failed with:

```text
Protected credential storage is unavailable.
```

Because the provider API verification succeeded before this message, the observed failure is not the Refrens authentication/API path. The exact user-facing message is emitted by the initial `CredentialStore` keyring import/dependency boundary, before OS-keyring backend selection or credential persistence.

## Confirmed certification coverage gap

The tagged `v1.0.0.1.38` GitHub Actions run successfully exercised the real Windows `CredentialStore` round trip in the clean installed-wheel Python environment. However, the later Nuitka OneDir and MSI smoke stages checked compiled application startup/database creation only. They did **not** execute `CredentialStore.set_credentials()`, `get_credentials()` and `delete_credentials()` inside the compiled `Invio.exe` runtime.

The released compiled-runtime failure therefore exposed a P14 packaging/certification gap that the green workflow did not test.

## Scope-locked correction

`v1.0.0.1.39` does not replace keyring or weaken the protected-storage policy. It keeps `keyring>=25.7,<26` and the existing approved OS-backend allow-list/no-plaintext-fallback behavior unchanged.

The correction is limited to:

1. explicitly including the existing keyring runtime dependency graph in the pinned Nuitka standalone build;
2. preserving the `keyring` distribution metadata used by its backend discovery mechanism;
3. adding an explicit P14 compiled-runtime credential round-trip smoke that calls the production `CredentialStore` set/read/delete path in the OneDir executable and again in the MSI-installed executable;
4. adding a test-only application entry hook enabled only by `INVIO_P14_COMPILED_CREDENTIAL_SMOKE=1`;
5. release identity, regression tests and directly related documentation.

No Account workflow, Refrens/Stripe request semantics, database schema, Task state machine, WorkerManager, provider manifests, runtime dependency version, page, layout or normal-user UI behavior is changed.
