# Invio v1.0.0.1.31 - P12 Forensic Verification Correction

**Status:** P12 COMPLETE / verification-corrected. P11 remains IMPLEMENTED / LIVE ACCEPTANCE PENDING.

## Corrected

- Central secret redaction now masks quoted JSON-style named secrets such as `accessToken`, `token`, `appSecret`, `api_key`, `secret_key` and `authorization` values even when the value is not already known from a stored Account credential.
- Recipient Delivery History no longer infers provider send acceptance from a recipient `Succeeded` result alone. `Provider Accepted` requires durable success evidence for the provider's send stage.
- Unresolved mutating operation evidence keeps the support row `Uncertain` even if a later recipient row claims success without reconciling the ambiguity.
- Conflicting historical primary/assigned account evidence causes recipient report generation to fail closed rather than silently selecting a latest account.

- P09 scheduling/rate/health behavior.
- P10 idempotency/restart recovery behavior.
- Stripe and Refrens provider-send requests/business flow.
- one Task = one QThread WorkerManager architecture.
- Task/customer/template/provider-manifest/dependency/UI-page contracts.
