# Invio v1.0.0.1.19

## P07 - Task State Machine and Resend Safety

This release completes P07 on the verified v1.0.0.1.18 P06 baseline. It makes Task execution actions deterministic and prevents known successful recipients from being silently included in a same-Task full resend.

### User-visible behavior

- **Ready:** Start is first-run-only and requires pristine counters.
- **Running:** Pause or Stop.
- **Paused:** Resume the same worker, or Stop.
- **Stopped:** **Resume Remaining** is available only when the exact current-session failed plus never-attempted set is safe.
- **Failed:** **Retry Failed** is available only when the exact current-session failed set is safe.
- **Completed:** no resend action; create a new Task for another full execution.

Successful recipients are excluded from Resume Remaining and Retry Failed. Repeated retries shrink to still-unresolved failures. Stop reconciliation keeps the send set and Task counters aligned.

### Restart boundary

SQLite remains schema v4 and does not yet persist recipient-level delivery identity. If Invio restarts, exact failed/pending email identities are not guessed from aggregate counters. Identity-dependent Resume/Retry therefore fails closed. P10 remains the durable delivery-ledger/recovery phase.

### Compatibility and scope

- P05 immutable snapshots and `Task.id` logical run identity are unchanged.
- P06 provider capability/preflight still runs before every permitted new worker attempt.
- WorkerManager remains one QThread per active Task.
- Account reservations remain held until Close Task.
- Existing injected runner registration remains first-run compatible; continuation is fail-closed because that API exposes no safe recipient subset.
- No SQLite migration, dependency change, provider manifest/send change, automatic retry/backoff/rate limiting, Refrens Task enablement, or P08+ implementation is included.
