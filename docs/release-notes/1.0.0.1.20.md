# Invio v1.0.0.1.20

## P07 Forensic Verification and Correction

`v1.0.0.1.20` re-audits the exact shipped `v1.0.0.1.19` P07 implementation and corrects three Task-control/state-integration defects without advancing the production roadmap.

### Corrected

- **Late terminal/control race:** a worker can queue `Completed` just before a valid late Pause/Stop action is accepted by the GUI. Because P07 intentionally forbids `Paused/Stopping -> Completed`, MainWindow now reconciles that late terminal signal to existing `Stopped` instead of attempting an invalid transition.
- **Stale worker controls:** Pause, Resume and Stop are enabled and accepted only while the existing WorkerManager thread is still active. This prevents stale control actions after a worker has already exited.
- **Safe-empty continuation truthfulness:** a proven-safe current-session continuation may contain zero unresolved recipients. Invio now reports that no recipients remain instead of incorrectly describing the recipient identity set as unavailable.

### Unchanged

- P07 First Run / Resume Remaining / Retry Failed recipient-selection semantics.
- P05 immutable Task execution snapshots and `Task.id` logical run identity.
- P06 provider capability/preflight validation.
- SQLite schema v4 and storage migration contract.
- WorkerManager implementation and one-QThread-per-active-Task architecture.
- Account reservation release only through existing Close Task behavior.
- Stripe/Refrens provider-send semantics and the Refrens P11 execution gate.
- Provider manifests, external runner registration API, dependencies and P08+ behavior.
