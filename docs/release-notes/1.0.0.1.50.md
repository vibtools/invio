# Invio v1.0.0.1.50 — Deterministic Dynamic Tags V1

## Scope

Phase 4 adds the owner-approved provider-neutral Dynamic Tags V1 feature over the accepted v1.0.0.1.49.9 baseline.

Supported exact tags:

- `#NAME#` — normalized recipient email local-part.
- `#EMAIL#` — normalized full recipient email.
- `#R5#` — deterministic random-looking 5-digit value (`10000`–`99999`) for the same Task+recipient.
- `#R11#` — deterministic random-looking 11-digit value (`10000000000`–`99999999999`) for the same Task+recipient.
- `#DATE#` — Task-creation UTC date formatted like `August 18, 2026`.
- `#DATE-NAME#` — weekday name from the same Task-creation UTC reference, such as `Tuesday`.
- `#YAAR#` — four-digit year from the same Task-creation UTC reference.

Unknown tag policy: `KEEP_LITERAL`. Unknown tag-like text remains literal. Matching is exact and case-sensitive.

## Approved rendering fields

- Settings → Default Customer Name, only when that Settings default contains a supported tag.
- Invoice Template → Memo.
- Invoice Template → Footer.
- Invoice Template → Customer Note.
- Invoice Template → Terms.
- Invoice Template → Item Description.

Recipient email and all non-target fields remain unchanged.

## Determinism and recovery

New Tasks capture Dynamic Tags version 1 and an immutable Task-creation UTC reference. R5/R11 values derive from Task identity + normalized recipient + tag with a stable SHA-256 namespace. Rendering therefore reproduces identical values for the same durable Task+recipient through retry, Resume Remaining, Retry Failed and restart recovery.

## Storage compatibility

Operational schema advances additively from v6 to v7. New columns persist customer-name provenance plus Task Dynamic Tags version/reference. Existing v6 rows migrate with provenance disabled and Dynamic Tags version 0, so existing captured executions keep their prior literal semantics.

## Provider boundary

Rendering occurs in the Invio host. Existing Stripe, Refrens and external-provider payload/context mappings consume recipient-rendered copies without a provider-interface change. Unsupported provider fields remain unsupported.

## Frozen boundaries

No change to Phase-1 TLS, Phase-2 fatal-limit circuit breaker, Phase-3 timeout/retry/delay/rate controls, Retry-After/backoff/cooldowns, no-blind-replay safety, WorkerManager/QThread ownership, Task state machine, CredentialStore, OAuth/Easy Onboarding, IVX format, provider manifests, page inventory or unrelated UI/UX.
