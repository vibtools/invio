# Invio v1.0.0.1.10

## P03 - Account Lifecycle, Verification Health and Provider-Install Consistency

This release completes the approved P03 scope on top of the v1.0.0.1.9 Official Baseline Freeze.

### Account lifecycle

- Accounts page now provides **Edit**, **Re-test**, and **Delete** actions in addition to Add Account.
- Edit keeps provider identity fixed, is blocked while the Account is referenced by an open Task, and requires a new successful real API Test before any change is committed.
- Failed Edit verification leaves the previously saved Account and protected credential unchanged.
- Re-test verifies current protected credentials on a dedicated Qt worker thread. The result, UTC attempt time, and a credential-scrubbed safe error summary are persisted.
- A known failed Re-test remains fail-closed in current runtime memory even if the verification-health database update itself fails; a successful result is never promoted unless the durable write succeeds.
- Delete is blocked while any reservation or Task reference protects the Account. Protected credential deletion is coordinated with SQLite deletion and is restored if the database delete fails.

### Provider consistency

- A provider cannot be uninstalled while one of its Tasks has an active worker.
- Inactive provider uninstall removes only installation state. Existing Accounts, protected credentials, Tasks and reservations remain durable.
- Accounts belonging to an uninstalled provider remain visible under a **Not Installed** provider group.
- Edit/Re-test require the provider to be installed; Delete remains allowed when the Account is not Task-protected.
- Task Start/Retry fail closed before runner creation when the Task provider is not installed.

### Storage

- SQLite operational schema advances from v1 to v2.
- `accounts` gains `last_verification_at` and `verification_error_summary` only.
- Existing schema-v1 databases are backed up and migrated transactionally.
- Provider secrets remain in the approved OS-protected keyring and are not added to SQLite/settings/log persistence.

### Explicitly unchanged

No new page, dependency, ProviderManager/WorkerManager architecture, provider manifest, provider send behavior, Customer contract, Invoice Template contract, Task state machine, retry/rate-limit engine, or P04+ capability is introduced.
