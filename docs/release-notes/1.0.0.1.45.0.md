# Invio v1.0.0.1.45.0 — Providers Page Transient-Window + Compact Status Fix

**Official Parent Baseline:** Invio v1.0.0.1.44.0

## Scope

- Fix the brief small white `Invio` window seen during application construction and whenever Providers Page refreshes.
- Move `Available` / `Verified` from below the provider logo to directly below Provider Name.
- Compact only that status mark and reduce only the Provider card height implied by the shorter header.

## Root cause

`ProvidersPage.refresh()` creates new provider-card `QFrame` objects without parents. The previous `_reflow_cards()` called `setVisible(True)` before `QGridLayout.addWidget(...)` re-parented those cards into the page host. On Windows, the visible parentless `QFrame` becomes a temporary native top-level window; because the application name is Invio, the brief blank/white window is titled `Invio`. The same path runs during startup because `ProvidersPage` is constructed and refreshed while `MainWindow` registers all pages.

## Correction

- `_reflow_cards()` first hides all cards.
- Visible cards are added to the Providers grid, establishing parent ownership.
- Only after `grid.addWidget(...)` are those cards shown.
- Provider badge is moved into the identity column below Provider Name.
- Badge height becomes 18px and Provider card height becomes 194px; 40px logo, 280px minimum card width, 16px grid/padding, search, 2–4 responsive columns, description ellipsis, version footer and actions remain intact.

## Compatibility

No provider API/runtime behavior, manifest/P13 contract, persistence/schema, WorkerManager, Task, invoice/customer/account business logic, dependency, Settings, Forms, Data Grid or non-Providers page workflow change is included. SQLite remains schema v5; P13 remains interface v1.
