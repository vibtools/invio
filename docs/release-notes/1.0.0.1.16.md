# Invio v1.0.0.1.16

## P05 forensic verification and consistency correction

This release re-audits the exact v1.0.0.1.15 P05 baseline and fixes only P05 execution-snapshot consistency defects. It does not implement P06 or change the application architecture.

### Fixed

- Normal post-P05 Task creation now fails if a captured immutable execution snapshot is missing or incorrectly marked `LegacyUnavailable`; legacy snapshot state remains reserved for migrated pre-P05 Tasks.
- Captured Task progress now requires processed/success/failed counters to agree with the immutable recipient snapshot. Invalid runtime updates are rejected, and invalid persisted counters fail closed on startup.
- Routine Task status/progress writes no longer rewrite the immutable snapshot-derived `total` column; they validate the total before updating mutable progress/status fields.

### Unchanged

SQLite remains schema v4. Task snapshot contents, `Task.id` run identity, WorkerManager, ProviderManager, Stripe/Refrens send semantics, provider manifests, dependencies and UI page structure are unchanged. Production progress remains 5/14 and P06 remains separately approval-gated.
