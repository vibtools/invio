# Invio v1.0.0.1.48.6

## Scope

**Accounts Page — Action Column & Context Menu UI Correction** with compact table/status polish over the frozen `Invio v1.0.0.1.48.5` baseline. Only Accounts-page table geometry, Accounts-scoped status/action presentation, row-menu popup placement, and directly required tests/release documentation change.

## Confirmed root causes

1. v1.48.5 leaves `ACCOUNT` as the only Stretch column while Provider/Status use content sizing, creating an overly wide Account area and a compressed right-side cluster.
2. The Action column was only 48px, which can clip or crowd the header/control.
3. The existing `QMenu(action_button)` was opened at a raw global point without an application-window/screen safe rectangle. The first v1.48.6 candidate bounded only to the application window; real Windows/offscreen evidence showed Qt additionally constrains popup placement to available screen geometry, producing deterministic test mismatches.
4. The recent flat-table update reused strong global filled status badges. The owner approved a more restrained Accounts-only brand treatment without changing global tokens.

## Correction

- `ACCOUNT` and `PROVIDER` share stretch space; `STATUS` is fixed at 132px and `ACTION` at 68px.
- Account/Provider headers are left-aligned; Status/Action are centered.
- Row action control is compact 30x24 and centered.
- Popup is right-aligned inward from the clicked action button and bounded to `Invio window ∩ current screen availableGeometry`; it opens above the button when required.
- Accounts status badges are compact outline-style using success token `#22C55E`, warning `#FCD34D`, danger `#F87171`, neutral existing muted/border tokens; action focus/press uses primary `#2563EB`.
- Global Vib Tools token values remain unchanged.
- Existing Search, filters, pagination, Edit/Re-test/Delete callbacks and all backend behavior remain unchanged.
