# Invio v1.0.0.1.25

## P09 - Multi-Account Scheduling, Limits and Health

- Preserves `recipient_ordinal_round_robin_v1` and the frozen P05 account order as the primary assignment.
- Adds Stripe Task pacing at 20 API requests/second/account with burst capacity 1.
- Adds runtime-only account/provider health with bounded 5/10/20/40/60-second cooldown progression and `Retry-After` extension.
- Allows deterministic circular fallback only for not-yet-attempted recipients whose primary account is cooling from a recognized account-scoped Stripe rate-limit condition.
- Tracks attempted recipients in current-session delivery state so Resume/Retry cannot cross-account replay a recipient that already entered provider execution.
- Applies provider-wide cooldown without account hopping for timeout/disconnect/408/5xx.
- Blocks repeated account network use after 401/403 until successful account verification clears the runtime-only health state.
- Keeps deterministic validation/customer/template/operation failures non-failover.
- Keeps one Task = one QThread and intra-Task concurrency = 1.
- No P10 ledger, schema migration, dependency, Refrens Task enablement, Agiled execution, plugin architecture, Settings or new UI page.
