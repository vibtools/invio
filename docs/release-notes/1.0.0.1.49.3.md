# Invio v1.0.0.1.49.3 — Provider IVX Package System V1

**Official Parent Baseline:** `Invio v1.0.0.1.49.2` owner-approved replace-ready state.

## Scope

This release changes only external provider distribution/import and provider-card visual resolution. A provider can now be delivered as one `.ivx` file, internally a standard ZIP archive with root-level `provider.json`, conditional `adapter.py`, optional `logo.png`, documentation and optional `SHA256SUMS.txt`.

## Behavior

- **Load Provider** prefers `*.ivx` and keeps the legacy direct `provider.json` path.
- IVX Load never executes `adapter.py`; it validates and imports package data only.
- Safe packages are staged and atomically stored at `providers/packages/<provider_id>/` based on manifest ID, not archive filename.
- Built-in package directories cannot be replaced by IVX imports.
- Imported executable providers are still activated only by **Install**, with the existing trusted-code confirmation and P13 adapter validation.
- Imported package `logo.png` is preferred when valid; current built-in provider icons remain unchanged; missing/invalid plugin logos use `assets/icons/providers/fallback.png`.
- `scripts/provider/build_ivx.py` creates deterministic rooted IVX files and regenerates/validates package checksums.
- The current Zoho Books, Zoho Invoice, Xero, QuickBooks Online and Square v1.2.0 provider sources are repackaged as IVX without changing provider runtime versions or API/send behavior.

## Security

IVX rejects path traversal/absolute/Windows-drive/backslash paths, symlinks, encryption, duplicate/case-collision paths, invalid CRC/checksum data and configured archive resource-limit violations. Replacement is rollback-safe.

## Frozen boundaries

No Task/WorkerManager, storage/schema, Browser OAuth, Easy Onboarding, provider send/API, customer/template/report, MSI/WiX, dependency or unrelated UI behavior changes are part of this release.
