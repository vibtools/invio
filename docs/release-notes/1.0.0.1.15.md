# Invio v1.0.0.1.15

## P05 - Immutable Task Execution Snapshot and Input Consistency

This release implements the separately approved P05 scope on the verified `v1.0.0.1.14` baseline. It freezes the data/configuration of each newly created Task so later Customer List or Invoice Template edits cannot silently change that Task's Start or Retry behavior.

### Added

- Frozen Task execution contracts for ordered recipients, complete Invoice Template copy/items/terms, provider ID, ordered Account IDs and `recipient_ordinal_round_robin_v1` assignment basis.
- SQLite schema **v4** tables for durable Task execution snapshots.
- Atomic Task creation that persists Task metadata, account bindings, reservations and immutable snapshot rows in one transaction.
- Fail-closed migration marker `LegacyUnavailable` for pre-P05 Tasks whose historical inputs cannot be reconstructed truthfully.

### Execution consistency

- `Task.total` is derived from the immutable recipient snapshot count.
- Existing progress clamping uses that same total.
- ProviderRuntime uses the durable Task snapshot rather than current Customer List/Invoice Template contents.
- Start and Retry therefore use the same frozen recipients/template/provider/account ordering.
- `Task.id` remains the canonical logical run/idempotency identity. A different execution requires creation of a new Task.

### Legacy Tasks

Tasks created before schema v4 are retained with their existing status/counters/references/reservations but are marked `LegacyUnavailable`. Invio does **not** fabricate a historical snapshot from current mutable source data. Start and Retry are disabled; Close remains available to release Accounts before creating a new trustworthy Task.

### Preserved boundaries

- WorkerManager remains one QThread per active Task.
- P03 provider-install/account-verification gates remain intact.
- Stripe provider-send semantics and email-only compatibility are unchanged.
- Refrens production Task execution remains disabled until P11.
- P06 capability preflight, P07 state-machine/resend safety and P10 delivery ledger are not implemented here.
- No new dependency or UI page is introduced.
