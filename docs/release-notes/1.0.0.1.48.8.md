# Invio v1.0.0.1.48.8 — Canonical Status Column Natural-Width Runtime Correction

**Parent frozen state:** latest updated `v1.0.0.1.48.7` delta state.

## Scope

This release fixes only the confirmed Accounts status-column runtime sizing defect exposed by the owner's Windows PySide6 verification. It does not redesign the Accounts page and does not change the v1.48.7 global status-rendering architecture.

## Confirmed root cause

The v1.48.7 shared renderer already creates one canonical visible badge and gives the hidden `QTableWidgetItem` a size hint derived from that badge. However, the Accounts consumer then forced column 2 (`STATUS`) to `QHeaderView.Fixed` at 132px. The real Windows test measured the visible `✕ Not Installed` badge at 180px, so the consumer's fixed width could not satisfy the renderer's natural geometry contract.

New Task passed the same canonical-badge verification because its Status column already uses content-driven sizing. The defect is therefore isolated to the Accounts fixed-width override, not the shared status mapping, backend status value, or business logic.

## Correction

`AccountsPage` now uses `QHeaderView.ResizeToContents` for the Status column. The existing `set_data_status_cell()` item size hint is therefore authoritative and the column expands only as much as the actual status content requires in the current Qt font/DPI environment. `ACCOUNT` and `PROVIDER` remain stretch columns and `ACTION` remains the existing fixed 68px column.

## Preserved

- One canonical status badge per status cell.
- Success/warning/danger/neutral semantics and approved Vib Tools colors.
- Search, Provider/Status filters, pagination and rows-per-page.
- Edit/Re-test/Delete callbacks and context-menu geometry.
- Provider relationships, credentials, API tests, task reservations, storage/schema, WorkerManager, provider adapters and network/business logic.
