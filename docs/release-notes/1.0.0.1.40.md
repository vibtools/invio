# Invio v1.0.0.1.40 — Live Refrens/UI/Customer Defaults Correction Candidate

Status: **LOCAL SOURCE/LIVE CORRECTION CANDIDATE — DO NOT TAG OR RELEASE YET**.

Official owner-frozen parent baseline: **v1.0.0.1.39**.

## Scope

This correction is limited to the owner-reported v1.39 live-test failures and UI defects:

- dark-theme visibility for the New Task account list, Customer Lists tables, and popup/context menus;
- email-only customer import defaults, with Settings controls for default customer name and default customer country;
- Refrens create-invoice request correction for the live `terms` HTTP 400 failure;
- owner-provided application icon wiring through `assets/icons/app.png` and `assets/icons/app.ico` for source/runtime and Windows build metadata;
- version/test/documentation synchronization required by the same correction.

## Live failure evidence

The owner log proves Refrens account re-test succeeded, the Task was created after explicit customer data was supplied, and all seven recipients then failed at Refrens invoice creation with `HTTP_400` / `terms: Cast to embedded failed ... at path "terms"`. Retry Failed reproduced the same provider validation failure. This isolates the provider failure to the create-invoice payload rather than authentication, Task scheduling, or retry selection.

## Correction

`ProviderRuntime.build_refrens_invoice_payload()` no longer sends Invio's `list[str]` template terms in Refrens' create-invoice request. Refrens' published create-invoice request contract documents `billedTo`, `items`, and optional `email`, but not a request-side `terms` field. Invio still retains terms/customer-note/footer inside the immutable template snapshot; only the unsupported Refrens request representation is omitted.

Customer import now materializes provider-ready identity defaults at import time. A configured Default Customer Name applies to imported customers; otherwise missing names use the email local-part. A configured two-letter Default Customer Country applies when provided; otherwise existing explicit country is retained and missing country defaults to `US`.

## Icon prerequisite

The implementation references the owner-controlled files `assets/icons/app.png` and `assets/icons/app.ico`. These binary assets are not fabricated by this patch. Place the real files at those exact paths before local icon verification or Windows CI/build. `app.ico` is required by the pinned Nuitka Windows build option.
